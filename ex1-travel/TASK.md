# 實例一：台南旅遊規劃（第三章）— 主 Agent 任務

先讀 `../drill/ORCHESTRATION.md`（指揮子 Agent 的固定做法），session 名稱 `ex1`，資料夾 `ex1-travel`。

## 書中總提示詞（3.1，逐字）

```
請用三個子 Agent 規劃台南兩天一夜。

共同條件：兩位成人、不開車、預算 8,000 元，從台南火車站開始。
預算不含往返台南的交通費；日期尚未決定，日期相關資訊須標記待確認。

1. 景點 Agent：整理景點、停留時間、營業資訊及來源。
2. 交通 Agent：整理主要區域間的大眾運輸、步行時間與費用。
3. 預算 Agent：整理住宿、餐飲與交通的費用範圍和估算假設。

三個 Agent 均以表格交付，標示查詢日期、來源及不確定性。
若不能連網，明確標記無法查證，不得編造來源。

主 Agent 整合兩天行程、交通與總預算，保留休息及移動時間。
資料衝突時回查來源，無法確認的事項列為待確認。
```

## 子 Agent（三格平行）

| 格 | 角色 | 輸出 | 完成檔 |
| --- | --- | --- | --- |
| ① | 景點 | `out/attractions.md`（景點名稱、建議停留、營業資訊、費用、來源、查詢日期、狀態） | `out/景點.done` |
| ② | 交通 | `out/transport.md`（主要區域間路線、方式、時間、費用、來源） | `out/交通.done` |
| ③ | 預算 | `out/budget.md`（住宿、餐飲、交通的費用範圍、每人／兩人、估算假設、來源、狀態） | `out/預算.done` |

- 三個同時派（書中 3.2：平行）。交通與預算需要的景點位置，以「台南火車站周邊、中西區、安平」三個常見區域為假設前提，寫進各自 prompt。
- 責任界限：景點 Agent 不決定交通班次，交通 Agent 不編造景點資訊；三方都用 WebSearch 查證，查不到標「無法查證」，**絕不編造價格或來源**（書中 4.3 的錯誤示範：編造住宿 2,000 元/晚）。
- 不得執行任何訂房、付款或對外預訂。

## 主 Agent 整合

1. 收三份表，檢查每張表都有「查詢日期」「來源」欄；對照 8,000 元算總計（每人／兩人）。
2. 排兩天行程，保留休息與移動時間，無時間衝突。
3. 依 `plan-template.md` 的七項結構寫 `out/plan.md`。

## 驗收清單（書中 5.1）

- [ ] 行程包含停留、移動與休息時間，沒有時間衝突
- [ ] 費用區分每人與兩人合計，總計不超過預算
- [ ] 價格與營業資訊有來源或明確的待確認標記
- [ ] 未執行訂房、付款或其他對外預訂
- [ ] 行程表符合 plan-template.md 的七項結構
